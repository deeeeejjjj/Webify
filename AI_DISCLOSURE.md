### Record 8. Creators Can Sell Their Own Templates

| Field | Details |
|-------|---------|
| **AI Tool Used** | Claude Code (Claude Opus 5.5) |
| **Task Where AI Was Used** | Adding a feature that allows signed-in creators to upload, manage, and sell their own templates |
| **Manuscript/Project Section** | Template pages, creator dashboard, API routes, storage-related files, and application components |
| **Exact Prompt Used** | [P8](#p8--creators-can-sell-their-own-templates) |
| **Responsible Members** | Daniel A. Luto, Jessica S. Niduaza |

**AI Output Used:** The AI suggested and helped implement the following:

- A recommendation to show the template-selling option only to signed-in creators.
- A **"Sell Your Template"** button on the Templates page for signed-in creators.
- A form where creators can provide the template name, product type, business type, price, description, pictures, and confirmation that they own the design.
- A **"My Templates"** section in the creator dashboard where creators can manage or remove their uploaded templates.
- Help and FAQ information for the template-selling process.

**Validation Method:** The team checked the feature using different account types and tested the following:

- Users who were not signed in could not access the creator-only selling option.
- The template submission form displayed the required fields and validation messages.
- A template image was uploaded and its saved file size was checked.
- Submitted templates appeared under "My Templates" with the correct status.
- Uploaded templates could be removed after confirmation.
- The feature was checked across the Templates page and creator dashboard at different screen sizes.

> **Note:** The team documented that submissions were saved and displayed in the creator's browser. The feature was not yet validated through a complete production booking or payment process.

## C. Exact Prompts

### P1 – Frontend Build
*Record 1*

> Act as a senior frontend developer and help me build the project based on the information and requirements provided above. Create a fully functional, modern, and visually appealing frontend with smooth animations, interactive effects, and a user-friendly interface. Make sure the website is easy to navigate and understand, especially for older adults and users with limited technical knowledge.
>
> Follow the provided tools and technologies for the project, but focus exclusively on frontend development for now. Set aside database integration and backend functionality.
>
> Use the first reference image as inspiration for the overall layout and design, the second image as the reference for the blue branding and color palette, and the third image as the official project logo. Maintain consistent branding throughout the website.
>
> Prioritize accessibility, responsiveness, readability, and ease of use while maintaining a clean, professional, and engaging design.

**Sent with:** The project brief and three images.

### P2 – Project ZIP Preparation
*Record 2*

> Organize the complete Webify project into a clean, well-structured folder. Include all necessary source code, assets, stylesheets, scripts, and other project files. Remove unnecessary or duplicate files, maintain the existing functionality, and package everything into a single ZIP file.

### P3 – Real Photos and Full Template Designs
*Record 3*

> Replace all placeholder and draft images across the 20 Webify templates with high-quality, relevant real photos. Complete the visual design of all 20 templates, ensuring consistent styling, proper image placement, balanced layouts, and a polished, professional appearance. Keep all existing functionality intact and make sure every template is visually complete and responsive.

### P4 – Removing the Top Bar and FAQ Adjustment
*Record 4*

> Remove the fixed accessibility bar from the top of the website and adjust the FAQ section to its proper position. Ensure the layout remains clean, organized, and responsive without affecting other website elements.

### P5 – JSON Structure and Data Organization
*Record 5*

> Review the project's JSON files and explain how the data is structured, organized, and used throughout the application. Check for errors, inconsistencies, and unnecessary data while keeping the existing structure intact.

### P6 – Help Panel Improvements
*Record 6*

> Simplify the Help Panel by organizing its support options into a clean and user-friendly layout. Include page-specific guidance, helpful tips, and accessible Help Center links. Make sure everything is easy to understand and navigate.

### P7 – Repository Restructuring
*Record 7*

> Organize the project repository by properly grouping source code, public assets, and documentation into separate folders. Keep the file structure clean, consistent, and easy to maintain. Ensure all file paths and existing features continue to work.

### P8 – Creators Can Sell Their Own Templates
*Record 8*

> Add a feature that allows signed-in creators to upload, manage, edit, and sell their own templates. Include options for adding template details, uploading previews, updating information, and managing their listings. Ensure the interface is user-friendly and properly integrated with the existing application.
